# demo-it Mind Map

[1] **Project Architecture Overview** - Entry point for the transcript-driven demo system, linking the control surface [2], canonical execution model [3], transport contract [4], and development workflow [5].
[2] **Client Control Surface (CLI + Neovim Plugin)** - `demo-it` CLI and local Neovim commands act as thin clients that forward user intent over the daemon protocol [4], while CLI workspace tmux bootstrap mode (`start [path]` or direct `<path>` -> `<name>-demo`/`<name>-notes`) defaults to current working directory for `start`, requires `demo-it.md`, and can replay `demo-it` block actions (`insert-text`, `key`, `key-macro`, `open-slide`, `clear-panes`, `split-pane`, `split-pane-vertical`) plus step-level `slide` shorthand from `demo-it.md` with pane-safe behavior (`split-pane` keeps presenter focus, action inputs can optionally target pane selectors like `active`/`last`/index, slide changes target a Neovim pane via `slide`/`open-slide`/`key`+`slide` with auto-start, and `clear-panes` closes extra panes via repeated `C-d` while skipping terminal reset in Neovim panes), refresh speaker notes in the notes session as `next`/`prev` move through the latest workspace, expose workspace-step metadata in `next`/`prev`/`rerun` responses, report `DemoItNext`/`DemoItPrev`/`DemoItRerun` progress in-command-line as slide/step confirmation instead of popup dialogs, default `:DemoItStart` workspace bootstrap to Neovim's current working directory when no path is provided, enable builtin presentation mode by default on start (`DemoItPresentationEnable`) with zen-like low-noise window options, markdown rendered/raw conceal switching, and markdown-diagnostic suppression while active, light viewport padding, configurable font sizing (`presentation.font.neovide_scale` + `presentation.font.kitty_delta`) with Kitty bump/revert support, tmux demo-session `status off` defaults, and session navigation key table shortcuts (`C-s` then `n`/`p` -> `demo-it next`/`prev`) that call the CLI directly, expose preview wrappers (`DemoItPreview`, `DemoItPreviewStop`) that prefer `LivePreview` and fall back to `MarkdownPreview`, and expose lifecycle helpers (`list`, `notes`, `show`, `kill all`, `kill <index...>`) for managed tmux sessions in [5], all within the architecture map [1] and canonical state model [3].
[3] **Canonical Run State and Transition Engine** - `internal/session` owns run status, cursor/history transitions, and idempotent execution ledger semantics consumed by the daemon service via [4], exposed through the client surface [2], and anchored in the architecture index [1] and quality loop [5].
[4] **Daemon Service and Wire Protocol** - `demo-itd` + `internal/daemon` implement Unix-socket NDJSON request/response handling with validated command envelopes from `internal/protocol`, mediating between user-facing controls [2] and canonical state transitions [3]; request envelopes are minimal (`id`, `cmd`, `run_id`, `args`) without unused `client_id`, while state responses stay intentionally small (`run_id`, `status`, `current_slide`, transition metadata) and keep cursor-interaction/default-focus internals private; transcript parsing enforces unique `demo-it` block titles for deterministic step identity, all within architecture [1] and workflow [5].
[5] **Development Environment, Docs, and Verification** - Nix/devenv bootstrap, flake-packaged CLI/daemon outputs plus a shared Neovim plugin package (`packages.<system>.demo-it-nvim`) for nixvim consumers, Home Manager module support for running `demo-itd` as a persistent user service with shared socket environment (including documented flake wiring via `inputs.demo-it.homeManagerModules.default` and `services.demo-it.enable`), direnv integration, trusted project-local Neovim bootstrap (`.nvim.lua` + `exrc`), protocol/plan documentation, presentation workspace assets (`demo-it.md`, `slides/*`), and test boundaries provide the iteration framework that keeps control paths [2], runtime state logic [3], and daemon transport [4] coherent within the project overview [1].
